## Implemented policy and interfaces

Owner decisions on 2026-10-28: either-direction participant blocking hides the counterpart from authenticated discovery and freezes shared conversation/work mutations. It never cancels assignments, moves funds, erases history or revokes unrelated sessions. Authorized participants retain historical reads; active participants may escalate frozen work. Anonymous public profiles remain public: relationship blocking is not a promise of secret public content. Admin account moderation remains separate and cannot be reversed by unblocking a relationship.

`/safety/blocks` (GET/POST), `/safety/blocks/:id` (DELETE), `/safety/reports` (POST), `/safety/support` (POST), `/safety/cases` (GET), `/safety/assignments/:id/escalate-cancellation` (POST), and `/work-assignments/:id/cancellation/reject` (PATCH) are authenticated marketplace APIs. Self-block/report and administrator targeting for blocks are denied. Active directional blocks are idempotent and historical unblock cycles remain stored. Reports require a valid category and 10?2000 character reason; context must belong to the participants. Targets never receive report details or reporter identity. Participant case lists exclude reports, including the reporter's own reports; submissions receive an opaque receipt.

Safety cases use a shared rolling 24-hour limit of ten submissions per actor and fifty new block cycles per actor, serialized on actor/pair database locks. Duplicate active requests return their existing record before quota checks. These engineering abuse limits are not cancellation deadlines or review SLAs. Anonymous abuse controls/proxy capacity still need deployment-level review.

Administrators use `/admin/safety/cases`, `/:id`, and `/:id/review`; roles/status are enforced by HTTP guards and rechecked for transactional decisions. Report/support decisions resolve or dismiss; cancellation decisions confirm cancellation, deny cancellation, or dismiss escalation. Reasons are mandatory, histories append-only through application APIs, audit failure rolls back mutation and notices, and a concurrent second decision returns conflict. First cancellation requests require a reason; counterpart confirmation remains compatible with an optional note. Pending/declined cancellation and frozen work can be escalated without an invented deadline. Payment-disputed assignments use the existing payment-dispute workflow; participant cancellation and cancellation rejection cannot change those records. No refund, settlement, penalty or automatic cancellation is implemented.

Marketplace `/safety` provides blocks, unblocking, support and private/shared permitted histories. Public profiles expose block/report controls to signed-in counterpart accounts. Assignment panels provide escalation outside the read-only mutation fieldset. Admin `/safety` provides a private queue, history and decision form. Authenticated support is not credential recovery; password resets, identity checks and blocked/deleted appeals remain product/provider gates.

Onboarding now reloads saved profile fields and links, clears successful upload selections before retrying later failures, deduplicates repeated portfolio submissions under a PostgreSQL user lock and permits transport of the existing maximum five one-MiB company PDFs with an eight-MiB action envelope. Per-file/count/type checks remain enforced by the API. Profile completion and optional document review retain their existing semantics; a saved profile does not imply every selected upload completed. After reload browsers cannot reconstruct file bytes: reselect unsubmitted files or use the existing profile/document settings. Partial multi-file provider failures/orphans still require staging reconciliation evidence.

## Remaining product/operational decisions

Credential recovery provider and identity evidence; blocked/deleted appeals and unauthenticated support access; complete erasure/retention/holds; named support/moderation/dispute owners and review expectations; orphan cleanup approvals; managed backup/PITR objectives; alert thresholds/destinations; actual HTTPS/storage hosting settings. General native deliverable attachments remain out of scope (existing link delivery works). Automated refunds, settlement, penalties, cancellation deadlines, native attachment hosting and legal compliance certification are not introduced.
